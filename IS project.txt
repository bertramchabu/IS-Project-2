Abstract
Network downtime in critical infrastructure environments poses significant economic and operational risks, with enterprises facing substantial losses per hour of disruption. Traditional network monitoring systems remain predominantly reactive, relying on threshold-based alerts that trigger only after service degradation has occurred [1]. This research proposes NetVision AI, an intelligent network monitoring dashboard that integrates a Bidirectional Long Short-Term Memory (BiLSTM) neural network with a responsive Flutter-based user interface to enable proactive fault anticipation [2]. The study aims to achieve three primary objectives: first, to develop a dashboard with interactive map layers and real-time KPI graphs refreshing at one-second intervals; second, to train a BiLSTM model achieving an F1-score of at least 0.85 and RMSE not exceeding 0.10 using multivariate network metrics [3]; third, to implement an adaptive alert mechanism that generates notifications within two seconds of fault detection while reducing computational load by 90% during normal network conditions [4]. The methodology adopts a prototyping approach, encompassing requirements gathering, iterative design, user evaluation, and systematic testing. The BiLSTM architecture is selected for its ability to capture temporal dependencies in both forward and backward directions, making it particularly suitable for detecting fault precursors distributed across time-series data [5]. Evaluation will compare NetVision AI against conventional threshold-based systems using prediction accuracy, detection latency, and the System Usability Scale [6]. This research addresses a critical gap in African network management literature, offering a proactive, resource-efficient solution for infrastructure reliability.

Keywords: Network monitoring, fault anticipation, BiLSTM, predictive maintenance, Flutter, dashboard usability, alert fatigue

Chapter One: Introduction
1.1 Background Information 
In contemporary enterprise networks and cloud-based infrastructures, maintaining continuous and reliable network operation has become paramount to organizational success. Issues such as undetected performance degradation, hardware failures, and routing anomalies can precipitate substantial financial losses, data breaches, and significant operational slowdowns. Research by (Albattat, Albaker, & Alsaedi, 2025) demonstrates that AI and IoT-powered smart maintenance methods have revolutionized industrial application domains, yet network management has lagged in adopting these advances. Traditional monitoring solutions predominantly employ reactive alerting mechanisms that trigger only after service interruptions have occurred compelling network administrators to engage in remedial actions post-failure.
Recent work by (Azeta, et al., 2025) provides a comprehensive review of artificial intelligence and robotics in predictive maintenance, highlighting that deep learning architectures have transformed how faults are anticipated across industrial systems. Among these architectures, Bidirectional Long Short-Term Memory (BiLSTM) networks have demonstrated superior capability in capturing complex temporal dependencies within sequential data by processing information in both forward and reverse directions. (Jiang, 2025) propose an AI agent-enabled predictive maintenance framework that serves as a conceptual foundation for intelligent monitoring systems, emphasizing the importance of real-time fault anticipation.
The security risks associated with network anomalies have intensified due to the exponential growth of connected devices across smart homes, healthcare, and industrial control systems. Research by (Mishra, Tripathi, & Sharma, 2026) presents a hybrid Convolutional Neural Network and Bidirectional Long Short-Term Memory (CNN+BiLSTM) framework for real-time anomaly detection, specifically designed for edge deployment on resource-constrained devices. This framework demonstrates that lightweight temporal models can achieve effective anomaly detection without excessive computational overhead.
Network operations teams across Africa remain predominantly constrained to reactive incident response models. The Communications Authority of Kenya has documented rapid growth in network-dependent infrastructure, including mobile money platforms and digital government services, yet local research on automated, predictive monitoring systems remains significantly underdeveloped. (Hornyak, 2026) demonstrates that LSTM networks effectively capture temporal failure patterns in multivariate sensor data, achieving strong predictive capability across both individual and aggregated machine groups. NetVision AI addresses this gap through an intelligent dashboard leveraging Flutter for front-end responsiveness and a BiLSTM neural network for predictive analytics, synthesizing diverse data streams to identify potential faults before service disruption occurs.
1.2 Problem Statement
Network downtime in critical infrastructure environments—including telecommunications, industrial automation, and smart city systems—presents substantial economic and safety risks. Contemporary research identifies three interrelated gaps that collectively undermine network reliability in mission-critical deployments.
First, traditional monitoring tools cannot analyse multivariate time-series data in a collective, integrated manner. (Sheng He, 2026) addresses this challenge through graph-based dual-contrastive representation learning for multivariate time series anomaly detection, demonstrating that capturing both temporal and inter-variable dependencies is essential for accurate fault identification. Studies on metrics including latency, jitter, packet loss, retransmission rates, and signal strength are conducted independently, which impedes the detection of degradation trends prior to complete failure. This siloed analytical approach means administrators observe individual metrics crossing predetermined thresholds but fail to recognize synergistic relationships until after actual faults have occurred.
Second, poor dashboard design directly compromises administrator performance during critical incidents. (Tziakouris & Al-Fardan, 2025) propose a comprehensive cognitive fatigue detection system for mission-critical operational environments including NOCs and SOCs, documenting that sustained vigilance demands lead to cognitive overload, delayed threat detection, and dismissal of legitimate alerts. Their research demonstrates that after six hours of continuous monitoring, analyst response time slows by over 35%, with eye-tracking revealing prolonged fixations and reduced engagement. Ineffective visualization reduces user satisfaction, focus, and situational control during time-sensitive troubleshooting, causing delayed incident response.
Third, static fault-tolerance mechanisms impose unnecessary computational overhead. (Catalin, 2026) present deep neural network-based fault diagnosis for predictive maintenance, demonstrating that adaptive inference mechanisms can significantly reduce computational waste. Existing systems maintain continuous monitoring and alerting activity irrespective of network health status, consuming substantial bandwidth overhead even under nominal conditions. (Soliman, Mikkelesen, & and Seljåsen) examine the battle between mindfulness and mindlessness in Security Operations Centres, revealing that analysts face 50% to 90% false positive alerts, leading to desensitization and cognitive overload that raises the risk of successful attacks.
Consequently, network administrators can only identify issues after service delivery interruption has occurred. (Workato, 2025) reports that SOC teams face an average of 3,832 alerts daily, with 62 percent being entirely ignored. Post-failure identification causes economic losses, security vulnerabilities in industrial control systems, and organizational inefficiency. Until organizations acquire tools enabling proactive fault identification without resource wastage during normal operations, unnecessary downtime will persist.

1.6 Scope 
The project will entail designing, developing, and evaluating NetVision AI, an intelligent dashboard for web-based network management. The platform will collect network KPIs consisting of latency, jitter, packet loss, retransmission rates, and signal strength as multivariate time series to predict fault probability. Prediction will be performed using a BiLSTM neural network algorithm on simulated network fault data due to limited access to live data arising from security and confidentiality requirements.
The dashboard will be implemented using the Flutter platform based on Bloc architecture for state management. Interactive map layers for geographical visualization, real-time KPI graphs with one-second updates, and configurable alert functionality are included in the implementation. Evaluation will cover fault anticipation accuracy (F1-score and RMSE), improved response times, and ease of use (System Usability Scale).
Physical network hardware integration will not be considered in the process. Network data stream simulation or import from existing logs (CSV files or API streams from simulated environments) will be used. Remediation steps such as restarting services or rerouting traffic are strictly excluded from scope.
1.7 Limitations and Delimitations 
Limitations 
The BiLSTM model’s prediction accuracy depends on the quality and availability of labelled network fault datasets, which may be limited or require synthetic generation (Azeta, et al., 2025) . Real-time network data streaming may be constrained by institutional network policies or data access restrictions. Usability testing will involve a limited number of administrators due to time constraints, which may not fully represent all user populations (Soliman, Mikkelesen, & and Seljåsen).
Delimitations
The study will focus on five key network KPIs and will not include other metrics such as bandwidth utilization or device CPU load (Sheng He, 2026). The predictive model will be designed for fault anticipation only, not performing automated remediation or fault correction (Jiang, 2025). The system will be evaluated in a simulated or controlled environment, not on a live revenue-critical production network. Development will prioritize web-based deployment, with native mobile features considered out of scope for this phase.


















Chapter 2: Literature Review
2.1 Introduction 
The literature review in this chapter presents a thorough assessment of literature pertaining to the design, development, and evaluation of AI-based intelligent network monitoring systems. This chapter begins with a discussion of network monitoring systems and their evolution from purely reactive to more proactive approaches. An assessment of how artificial intelligence, particularly time series learning algorithms like LSTM and BiLSTM, has been applied to network fault detection and prediction is presented. Literature on the design and usability aspects of network dashboards is critically evaluated. Following this, a review of available AI-enabled network monitoring systems and their limitations is discussed. This chapter concludes with a conceptual framework derived from the literature review. 
2.2 Evolution and Current State of Network Monitoring Systems
2.2.1 Traditional Reactive Monitoring Approaches 
Network monitoring has historically been a reactive field. Conventional systems including SNMP-enabled tools, Nagios, Zabbix, and Cacti primarily rely on threshold-based alerting mechanisms. (Albattat, Albaker, & Alsaedi, 2025) document that while these systems gather required information periodically and evaluate collected data against predefined thresholds, this approach has inherent drawbacks including inability to adapt to dynamic network conditions and failure to capture complex interdependencies between metrics. 
The most evident weakness is that threshold monitoring only recognizes failure after it has occurred. (Azeta, et al., 2025) note that by the time metrics reach threshold levels, service performance degradation may already have been experienced by customers. (Workato, 2025) similarly highlights high alert volumes in operations centres, indicating that reactive workflows can overwhelm analysts and delay effective response. 
Furthermore, static thresholds cannot adapt to dynamic network and traffic patterns. (Sheng He, 2026) demonstrates that quasi-periodic network time series consist of complex interdependencies that cannot be observed using single-parameter analysis alone, requiring advanced multivariate approaches for effective anomaly detection.
2.2.2 Proactive Maintenance Paradigm 
The drawbacks of reactive monitoring have motivated researchers to explore proactive maintenance methods. (Jiang, 2025) propose an AI agent-enabled predictive maintenance framework where faults are identified before they lead to service interruptions. Their framework emphasizes the integration of intelligent agents that continuously learn from operational data to anticipate failures.
(Hornyak, 2026) presents an LSTM approach for fault prediction using multivariate time-series sensor data, demonstrating that deep learning models can effectively capture temporal failure patterns. The study utilizes publicly available predictive maintenance datasets and achieves outstanding accuracy in certain configurations, confirming strong predictive capability across both individual and aggregated machine groups.
(Storey, 2025) explores dynamic orchestration of distributed streaming analytics in edge-integrated cloud platforms for real-time event detection, highlighting that edge computing reduces latency and bandwidth consumption while enabling faster response to detected anomalies. This aligns with the proactive maintenance paradigm where computational resources are distributed to enable real-time fault anticipation.
2.3 Artificial Intelligence for Network Fault Anticipation 
2.3.1 Time-Series Learning Models 
Time series analysis is common practice in network monitoring. Metrics including latency, jitter, and packet loss are collected sequentially, forming multivariate time series. (Mishra, Tripathi, & Sharma, 2026) present a real-time edge-deployed LSTM framework for IoT botnet and DDoS anomaly detection, demonstrating that deep learning methods, particularly LSTM architectures, can effectively process sequential data for anomaly identification. Their system uses MQTT to ingest live network traffic, preprocesses feature in real time and applies learned models to locally identify anomalies. 
(Catalin, 2026) present deep neural network-based fault diagnosis using CNN architectures operating on 2D time-feature representations of multivariate signals, achieving 92.31% accuracy on holdout validation. This demonstrates that deep learning approaches can effectively classify multiple fault types under varying operating conditions.
(Sheng He, 2026) introduces GDCMAD, a graph-based dual-contrastive representation learning method for multivariate time series anomaly detection. The method constructs relational graphs for capturing inter-variable and temporal dependencies, integrating an improved Kolmogorov-Arnold network-based attention mechanism into a reconstruction framework with an LSTM-based external contrastive learning module. Experimental results across six public datasets show superior anomaly detection performance compared to nine state-of-the-art methods. 
2.3.2 Bidirectional LSTM (BiLSTM) for Fault Anticipation 
Recent research has established BiLSTM as a highly effective architecture for fault anticipation in time-sensitive networks. The MDPI study on BiLSTM-based fault anticipation for predictive activation of FRER (Seliem, 2025) provides comprehensive evidence that BiLSTM networks, by processing sequences in both forward and reverse directions, enable inclusion of both past and future context into each hidden state. This bidirectional processing is particularly valuable for fault anticipation since fault indications may be present both before and after the examined time point. 
The study demonstrates that BiLSTM-based models perform better than traditional statistical models and other LSTM-based techniques in fault anticipation, improving the timing and reliability of redundancy activation in time-critical industrial networks. The model proves particularly effective at identifying faults with gradual onset whose precursors are distributed throughout a time interval rather than concentrated immediately before fault occurrence.
(Tang, 2026) introduces VAML-Net, a composite architecture for unsupervised anomaly detection within multivariate time series using variational autoencoder and multiresolution LSTM, specifically tailored to heterogeneous data and distributed network environments. The work proposes methods that adapt to inherent non-stationarity and noise present in real-world time series data. 
2.3.3 Alternative AI Approaches for Network Monitoring 
While BiLSTM has been selected as the neural network model for this research, various AI techniques have been applied to network monitoring and fault detection. (Mishra, Tripathi, & Sharma, 2026) utilize CNN+BiLSTM hybrid frameworks for real-time anomaly detection, demonstrating that combining convolutional feature extraction with bidirectional temporal processing enhances detection accuracy.
(Catalin, 2026) demonstrate that CNN architectures operating on 2D time-feature representations achieve strong fault classification performance (92.31% accuracy), though these are less efficient at detecting long-range temporal dependencies than recurrent networks.
(Sheng He, 2026) present graph neural network approaches for multivariate time series anomaly detection, constructing relational graphs that capture both temporal dependencies and inter-variable interactions. This represents an emerging direction for network monitoring that incorporates topological information. 
BiLSTM stands out as the optimal choice for NetVision AI, providing appropriate balance between performance and efficiency, demonstrating proven effectiveness in forecasting faults from time series data, and enabling lightweight model deployment for real-time inference (Tang, 2026). 
2.4 Dashboard Design for Network Management 
2.4.1 User-Centred Design Principles
Beyond prediction quality, any monitoring system’s effectiveness depends substantially on how well analysis results are conveyed to human administrators. (Tziakouris & Al-Fardan, 2025) emphasize that ineffective visualization can undermine advantages even from sophisticated machine learning algorithms, proposing a comprehensive system that fuses cognitive load analytics with real-time behavioural telemetry.
(Soliman, Mikkelesen, & and Seljåsen) examine the battle between mindfulness and mindlessness in SOCs, revealing that user-centred design principles significantly impact analyst effectiveness. Their research identifies that SOCs as High-Reliability Organizations require characteristics including preoccupation with failure, reluctance to simplify interpretations, sensitivity to operations, commitment to resilience, and deference to expertise.
(AlertOps, 2025) documents that organizations implementing intelligent dashboard designs with contextual alert information reduce noise by 70% and improve mean time to resolution by 35%, demonstrating the critical importance of user-centred design in monitoring systems.
The System Usability Scale (SUS) remains a widely used instrument for assessing perceived usability, with scores above 68 generally interpreted as above average and scores above 80 indicating excellent usability (Tziakouris & Al-Fardan, 2025).
2.4.2 Visualization for Network Time-Series Data 
Time series data pose unique visualization challenges. Metrics fluctuate rapidly over time, typically exhibiting high dimensionality (numerous metrics per node) and high cardinality (numerous nodes). The Cote Network Logger package (Cote Network Logger, 2025) demonstrates modern approaches to real-time HTTP network monitoring with web dashboards, featuring glass-morphism design, real-time WebSocket updates, complete request/response views, and advanced filtering capabilities—serving as a reference for contemporary dashboard design patterns.
(Storey, 2025) discusses visualization requirements for edge-integrated cloud platforms, emphasizing that real-time event detection systems require rapid updating displays (one-second intervals for critical metrics), consistent colour schemes, and display of both absolute values and trend information.
2.4.3 Alerting Mechanisms and Human Factors 
Alerting involves notifying administrators of detected or predicted problems through monitoring systems. (Workato, 2025) reports that SOC teams face an average of 3,832 alerts per day, with 62 percent being ignored entirely. This phenomenon, termed alert fatigue, occurs when excessive alerts requiring no action desensitize administrators to genuine threats.
(Tziakouris & Al-Fardan, 2025) demonstrate that after six hours of continuous monitoring, analyst response time slows by over 35%, with eye-tracking revealing prolonged fixations and reduced saccadic movement. Their proposed system computes a Fatigue Risk Index (FRI) using multi-modal data models, fusing biometric signals with system activity trends to issue intelligent alerts and suggest task rotation. 
(Soliman, Mikkelesen, & and Seljåsen) reveal that analysts employ “mindful balancing” tactics to alternate between mindfulness and mindlessness to manage demanding work, noting that 50% to 90% of alerts are false positives, leading to a state of desensitization that raises the risk of successful attacks. 
Alert effectiveness can be significantly improved through context-aware design. (AlertOps, 2025) demonstrates that dashboards providing alert severity signals, cause information, and suggested actions enable faster, better responses compared to systems lacking such context. 
2.4.4 Usability Evaluation Methods 
The System Usability Scale (SUS) remains one of the most widely used instruments for evaluating perceived usability in information systems. It comprises ten statements rated on a five-point Likert scale, producing overall scores between 0 and 100. The scale has been validated across numerous information system domains, including network monitoring dashboards.
2.5 Review of Existing AI-Integrated Network Monitoring Systems
2.5.1 Real-Time Edge-Deployed Anomaly Detection 
(Mishra, Tripathi, & Sharma, 2026) present a real-time edge-deployed LSTM framework for anomaly detection, specifically designed for edge deployment on resource-constrained devices like Raspberry Pi. The system uses MQTT to ingest live network traffic, preprocesses feature in real time and applies learned models to locally identify anomalies. A Streamlit-based dashboard provides visual representation of identified threats. The multi-phase implementation includes robust data preprocessing, model training with class imbalance handling and hyperparameter optimization, and real-time inference at the edge. Standard IoT datasets including UNSW-NB15 and BoT-IoT are used for evaluation.
2.5.2 Predictive FRER Activation in Time-Sensitive Networks 
The comprehensive study on BiLSTM-based fault anticipation for predictive activation of FRER (Seliem, 2025) provides strong evidence for anticipatory redundancy strategies. The framework monitors multivariate network performance indicators including latency, jitter, and retransmission rates, applying a BiLSTM model to forecast imminent fault likelihood. FRER is selectively enabled for affected streams when predicted fault scores exceed dynamic thresholds and deactivated upon KPI recovery or timeout expiry. Experimental results demonstrate substantial improvements in link utilization while preserving fault protection, with approximately 40% bandwidth overhead savings under regular conditions. 
2.5.3 Graph-Based Multivariate Time Series Anomaly Detection
(Sheng He, 2026) proposes GDCMAD, a graph-based dual-contrastive representation learning method that addresses challenges of limited data representation and insufficient discrimination ability. The method transforms multivariate time series into graph structures from two perspectives (temporal dependency and variable interaction), employs graph neural networks to extract features, and uses contrastive learning to learn richer representations. This represents an emerging approach that combines topological awareness with temporal modelling.
2.5.4 Network Datasets for Model Training
Machine learning models for network fault detection require representative datasets for training. (Seliem, 2025) utilize UNSW-NB15 and BoT-IoT datasets for evaluation of their anomaly detection framework. However, (Hornyak, 2026) notes that publicly available datasets often focus on security attacks rather than network faults. For this project, simulated data will be generated to train the BiLSTM model due to limited access to production network data with labelled fault events. 
2.5.5 Cognitive Fatigue and Human Factors in Monitoring 
(Tziakouris & Al-Fardan, 2025) present a comprehensive system for detecting operator fatigue in mission-critical environments leveraging fusion of cognitive load analytics with real-time behavioural telemetry. The system integrates biometric monitoring (eye movement, facial micro-expressions, heart rate variability) with contextual digital behaviours (keystroke patterns, alert triage timing, application usage entropy, attention-switching dynamics) to provide continuous, adaptive views of operator cognitive state.
(Soliman, Mikkelesen, & and Seljåsen) contribute the concept of “mindful balancing,” where analysts alternate between mindfulness and mindlessness to manage demanding work in SOCs. Their qualitative investigation across five SOCs reveals that maintaining chronic mindfulness exacts a heavy toll on individual cognitive resources, making security analysts particularly vulnerable to adverse effects of sustained mindfulness.
2.5.6 Limitations of Existing Solutions
Several notable challenges persist among existing solutions. First, current solutions concentrate predominantly on prediction-related metrics while treating usability as secondary (Tziakouris & Al-Fardan, 2025). Second, solutions are developed primarily for specific environments, with enterprise network KPI characteristics differing substantially from industrial sensor networks (Seliem, 2025). Third, computational resource management during normal operation is rarely considered (Storey, 2025). Fourth, dashboard development is frequently disregarded during AI-based monitoring system design (Cote Network Logger, 2025). Fifth, research on artificial intelligence for network monitoring in Africa remains absent (Communications Authority of Kenya, 2023). Sixth, existing solutions fail to address cognitive fatigue and human factor challenges that significantly impact monitoring effectiveness (Soliman, Mikkelesen, & and Seljåsen)
2.6 Identified Research Gaps 
After critically reviewing current literature, the following research gaps requiring attention through the proposed research are identified:
Underutilization of synergy between BiLSTM prediction models and user-centred dashboards. Although evidence demonstrates BiLSTM models can be effectively used for fault prediction (Seliem, 2025) and user-centred design principles lead to improved dashboard interaction (Tziakouris & Al-Fardan, 2025), no attempts to integrate these technologies have been identified.
Lack of resource management techniques for dashboard-integrated AI-based fault detection systems. All currently available solutions implementing AI fault detection involve continuous prediction execution (Mishra, Tripathi, & Sharma, 2026) (Hornyak, 2026).
Poor evaluation of AI-based monitoring system usability. Most studies provide prediction accuracy measures, but few include standardized usability evaluation within AI-driven monitoring workflows.
Lack of comparative evaluation relative to traditional methods. Many AIS for network monitoring studies discuss system performance without comparative analysis relative to conventional threshold techniques (Workato, 2025).
Scarcity of studies for networks within Africa. Most AI for network monitoring research has been conducted in North America, Europe, and East Asia, with few validation studies for African network environments (Communications Authority of Kenya, 2023).
2.7 Conceptual Framework
The conceptual framework illustrated in Figure 1 depicts the relationship between independent, dependent, and moderating variables underpinning NetVision AI. The independent variables consist of five multivariate network Key Performance Indicators (KPIs)—latency, jitter, packet loss, retransmission rates, and signal strength—collected as time-series data from the network environment. These metrics serve as primary inputs to the processing mechanism (Sheng He, 2026).
The processing mechanism comprises two interrelated subsystems. First, the BiLSTM neural network acts as the predictive engine, processing sequential dependencies in forward and backward directions to compute a fault probability score (Tang, 2026). Second, the adaptive threshold controller dynamically adjusts prediction rate based on current fault probability, reducing computational load by 90 percent when probability falls below 30 percent (Storey, 2025). The dependent variable is proactive fault anticipation, measured by prediction accuracy (F1-score ≥ 0.85, RMSE ≤ 0.10), detection time (≤ 2 seconds), and usability (SUS score ≥ 70).
The framework also acknowledges moderating variables including simulated dataset quality, network administrator experience levels during usability testing (Soliman, Mikkelesen, & and Seljåsen), and institutional network policies affecting data access (Communications Authority of Kenya, 2023). These variables are either controlled (through synthetic data generation) or noted as limitations per Section 1.7.

3.2 Research and Development Methodology
3.2.1 Choice and Justification of Methodology
This project adopts the Prototyping Methodology as the primary framework for guiding NetVision AI design and implementation. The Prototyping Methodology was selected based on four considerations supported by recent literature.
First, the project involves substantial uncertainty regarding BiLSTM model integration with a Flutter-based dashboard, making linear, plan-driven approaches unsuitable (Azeta, et al., 2025). Prototyping enables iterative refinement based on preliminary results from the model training phase. Second, the methodology supports early user feedback through iterative usability evaluations, aligning with user-centred design principles identified in the literature review (Tziakouris & Al-Fardan, 2025). Third, the project has clearly defined but interdependent objectives (the dashboard requires a functional model, while model architecture depends on dashboard refresh constraints), which prototyping manages effectively through successive cycles. Fourth, the risk of delivering an accurate but unusable model is mitigated by producing tangible, testable artifacts early in the development cycle.

3.2.2 Phase 1: Requirements Gathering
This phase establishes complete specifications of functional and non-functional requirements for NetVision AI. Requirements definition will be conducted through secondary data sources, consistent with delimitations stated in Section 1.6.
Specific activities in this phase include: analysis of the problem statement and objectives from Chapter 1 to derive system features; review of related works to identify benchmark requirements for F1-score (≥0.85) and detection time (≤2 seconds) (Tang, 2025); specification of five mandatory KPIs (latency, jitter, packet loss, retransmission rates, signal strength) as identified in Objective II; and documentation of technical constraints including Flutter as the front-end framework and the adaptive threshold mechanism specified in Objective III. The primary output of this phase is a Software Requirements Specification (SRS) document guiding all subsequent phases.
3.2.3 Phase 2: Quick Design
The quick design phase focuses on architectural and interface decisions required for constructing the first working prototype. This phase produces three categories of design artifacts: system architecture diagrams, database schema for storing historical KPI data and prediction logs, and initial dashboard interface wireframes including interactive map layers and three live KPI graphs specified in Objective I.
Design will adhere to the Bloc architecture pattern for Flutter state management to ensure one-second refresh intervals for the three KPI graphs. For the BiLSTM component, design will specify a lightweight architecture comprising an input layer (accepting sequences of five KPIs), two BiLSTM hidden layers (each with 64 units), a dropout layer (rate 0.2 for regularization), and a dense output layer with sigmoid activation producing fault probability between 0 and 1.
3.2.4 Phase 3: User Evaluation of Initial Prototype
In this phase, the first working prototype (Prototype V1) will undergo initial evaluation. Due to constraints stated in Section 1.7 (limited administrator access), user evaluation will involve five network administrators from the university’s ICT department, selected through purposive sampling based on their experience with conventional monitoring tools.
Evaluation will assess two dimensions. First, predictive performance will be measured by feeding a held-out test dataset (20 percent of simulated data, not used for training) through the BiLSTM model and calculating F1-score and RMSE per Objective II. Second, basic usability will be assessed using a pre-test version of the System Usability Scale (SUS) questionnaire focusing on visual alert clarity and KPI graph responsiveness. Feedback from this phase will be documented as a list of required modifications before proceeding to refinement.
3.2.5 Phase 4: Refining Prototype
This phase involves iterative improvement of both BiLSTM model and dashboard interface based on user evaluation feedback. Specific refinement activities include hyperparameter tuning of the BiLSTM (adjusting learning rate, batch size, number of epochs) to achieve target F1-score of 0.85 while maintaining RMSE ≤ 0.10; implementation of the adaptive fault detection threshold mechanism (default 70 percent probability for alerts, with prediction rate reduction by 90 percent when fault probability < 30 percent) as required by Objective III (Storey, 2025); enhancement of dashboard visual elements based on SUS feedback (colour schemes, alert positioning, map layer clarity); and optimization of the one-second refresh cycle for KPI graphs to eliminate frame drops or lag.
The outcome of this phase will be Prototype V2, taken forward for final testing.
3.2.6 Phase 5: Implement and Test (Final Prototype)
The final phase constitutes complete implementation and formal testing of NetVision AI. Implementation will involve integrating the refined BiLSTM model (exported as a TensorFlow Lite or ONNX runtime file) with the Flutter dashboard via a REST API or WebSocket connection for real-time predictions.
Testing will be structured into three categories corresponding to the four objectives. 
i.	Objective I testing (dashboard responsiveness) will verify that all three KPI graphs refresh within one second using automated UI test scripts. 
i.	Objective II testing (model accuracy) will compute final F1-score and RMSE on the test dataset and compare against targets. 
ii.	Objective III testing (alert timing and adaptive prediction) will measure time from threshold violation (fault probability ≥ 70 percent) to visual and audio alert generation and confirm prediction rate reduction by 90 percent when probability falls below 30 percent. 
iii.	Objective IV testing (comparative evaluation) will compare NetVision AI against a baseline threshold-based monitoring tool (simulated to have F1-score of 0.50 and detection time of 30 seconds) using the same test dataset and a SUS survey completed by the same five administrators.

4.2 Requirement Analysis
The requirement analysis procedure followed for the development of NetVision AI was based on a stakeholder-centric perspective since, in most cases, information systems fail due to assumptions made about the stakeholders’ requirements, rather than understanding them. Considering the criticality and urgency of the network environment, requirements were gathered using the analysis of secondary data, benchmarking against literature, and evaluation of the prototypes by practicing network administrators.
The main stakeholders for NetVision AI include:
i.	Network Administrator: The network administrator is the key operator of the system who will be responsible for constant monitoring of the status of the network, detecting any anomaly, and responding to the same. Currently, the network administrators work in a reactive model in which they must respond to threshold-based alerts after the occurrence of service degradation. The success of the network administrator is defined by the reduced mean time to detection, reduced volume of false-positive alerts, and enhanced situational awareness in critical scenarios.
ii.	ICT Manager: The ICT manager needs a bird’s eye view of network performance trends, alert volumes, and the effectiveness of the system to make informed decisions about infrastructure investments, hiring of personnel, and service level agreements. Performance of this stakeholder will be measured by reduced downtime costs, enhanced reporting ability, and evidence-based decision making.
iii.	System Administrator: The system administrator takes care of the NetVision AI system by performing activities such as managing the user accounts, training of models, setting up thresholds, and monitoring the overall health of the system. This stakeholder will require administrative activities to manage users, set up system parameters, and get audit logs.
iv.	Network Infrastructure (External System Actor): The network infrastructure is an actor that is a source of data and external system. Simulated network devices and monitoring endpoints will generate the data streams that will serve as the key performance indicators (KPIs) for the BiLSTM prediction engine.
v.	BiLSTM Prediction Engine (Internal System Actor): The BiLSTM prediction engine will act as an internal actor that processes multi-variate time series data and generates fault probability scores. This internal actor interacts with other components such as the dashboard, firestore, and alerting system.

4.4 Summary
This chapter has presented the comprehensive analysis and design of NetVision AI. The requirements analysis identified 48 functional requirements organised by actor and 18 non-functional requirements covering performance, accuracy, security, usability, reliability, scalability, maintainability, and compatibility. The design artefacts—including the use case diagram, class diagram, sequence diagrams, entity-relationship diagram, database schema, and wireframes—collectively provide a complete blueprint for implementation. The use case diagram illustrated the interactions between three human actors and two system actors within the defined system boundary. The class diagram specified the object-oriented structure with twelve principal classes. Three sequence diagrams detailed the dynamic interactions for real-time monitoring, alert acknowledgement, and report generation. The entity-relationship diagram and database schema provided the data model foundation with eleven tables and appropriate indexes. Finally, six wireframes illustrated the user interface design for the primary screens. These design artefacts are carried forward to Chapter 5 for implementation and testing.
